## [1.3.0] - 2026-11-18

### Added
- **`http` — a remote HTTP client on the facade** - `src/core/utils/http.ts` exports `http` (from `@/core/facade`): a small axios-backed helper for calling a server from the main process — `http.get/post/put/patch/delete/request`, plus `http.baseUrl()` and the raw `http.client` for interceptors. It reads `API_URL` at runtime, passes an absolute `http(s)://` URL straight through, fills in a missing scheme (`localhost:3000` → `http://localhost:3000`, `wallet.example.com` → `https://wallet.example.com`), JSON-encodes an object `body`, sets `Authorization: Bearer <token>` from `token`, and **never throws**: an unreachable server returns `{ ok: false, offline: true }`, so callers branch instead of catching. New `src/core/utils/http.test.ts`; exported from `src/core/facade.ts`; documented in the new `api/http.md` and `guide/remote-api.md`.
- **Calling a server API from the desktop** - `src/modules/app/controllers/net.controller.ts` exposes the generic `app.net.apiBase` and `app.net.apiFetch` bindings (thin wrappers over the facade `http`) so the renderer can call a remote server with no CORS and no third-party-cookie problem; the base URL is read from `.env` at runtime, so one build works for local and production. `API_URL` is documented in `.env`/`.env.example`; the dashboard "Network" card demos both handlers, and `src/ui/src/stores/server.ts` is a runnable store example. New guide page `guide/remote-api.md` (helper + controller + store + page, auth, offline, dev/prod, testing, and the renderer-axios alternative) with cross-links from `guide/controllers.md`, `guide/recipes.md`, `guide/ui.md` and `guide/realtime.md`.
- **Vite reads the project-root `.env`** - `src/ui/vite.config.ts` sets `envDir` to the project root and uses `loadEnv`, so `import.meta.env.VITE_*` (used by Pulse) and `__SOCKET_ENABLED__` reflect `.env` instead of only the shell environment. An optional `/api` dev proxy (same-origin forwarding for the renderer-axios route) is added only when `VITE_API_URL` is set.
- **Bearer auth for a nexwire server** - The desktop signs in to a nexwire server with a bearer token (the main process has no cookie jar). The client lives in **`src/config/auth.ts`** (app config — edit it for your server): the `AUTH` contract at the top (endpoints, session keys, request header, `refreshBody`, `readTokens`) and the mechanism below, so changing a token field name, a route, the header, or the response shape touches only that file. `src/main.ts` installs it with one import (`import "@config/auth";`), which puts two interceptors on `http.client` — a request interceptor attaches `<scheme> <access token>` (without overriding an explicit header) and a response interceptor turns a `401` into one silent `POST /api/auth/refresh-token` + retry, de-duplicating concurrent refreshes into a single rotation (the server rotates the pair). Every module therefore inherits auth with no wiring: call `http.get`/`http.post` and the token rides along. `src/modules/app/controllers/auth.controller.ts` is the thin binding surface (`app.auth.login`/`me`/`logout`/`status`) over it; the token pair is kept in the main process in the new `session` store (encrypted at rest with `safeStorage`) and never crosses to the renderer. `src/ui/src/stores/auth.ts` is the renderer half (login/me/status/logout, no token), and the dashboard gains an "Auth (bearer)" card. New `auth.schema.ts` (`LoginSchema`/`LoginType`), `app.facade.ts` re-exports `auth`, and `bindings.generated.ts` lists the six controllers. New `src/config/auth.test.ts` (contract, session helpers, both interceptors) and `src/modules/app/__tests__/auth.controller.test.ts` (handlers). Server side: nexwire 4.4.5's guard accepts the bearer header before the access cookie, and login/register already return `{ access_token, refresh_token, token_type }` in the body. Documented in `guide/remote-api.md` ("Authentication") and the new `api/auth.md`.
- **`session` — a main-process session store on the facade** - `src/core/utils/session.ts` exports `session` (from `@/core/facade`): a small keyed key/value store for per-user state in the main process — the deskapp counterpart of nexwire's framework `session`. `session.start/all/get/set/merge/refresh/destroy/flush/isAvailable/persistent` plus `session.DEFAULT`; each session has an optional `ttlMs` (`0` never expires, checked lazily on read). In-memory first (synchronous, never throws); when Electron's `safeStorage` is available it persists to `<userData>/session.enc` (ciphertext, never plaintext) and restores on the next launch, otherwise it stays memory-only and `persistent()` is `false`. New `src/core/utils/session.test.ts`; exported from `src/core/facade.ts`; documented in the new `api/session.md`.

## [1.2.5] - 2026-11-11

### Fixed
- **Realtime auth** - The Pulse client now sends the access token through the Socket.IO handshake (`auth` callback) instead of relying on an httpOnly cookie the Electron webview cannot set. After `pulse.setToken(...)`, the engine authenticates the socket and auto-joins `user:{id}`, `role:{role}`, and `auth` rooms; previously the socket stayed a guest even when signed in.
- **`pulse.setToken()`** - Accepts a token string, `null`, or a getter (resolved on every reconnect). Calling it while connected re-handshakes and re-joins all tracked rooms, and the `__SOCKET_ENABLED__ = false` no-op client implements it too.
- **`pulse.leave()`** - Now emits `leave` to the engine before dropping listeners, so the socket actually unsubscribes from the room; previously it only removed local listeners and kept receiving that room's events. Room names are trimmed consistently.

### Changed
- **Docs** - `guide/realtime.md` and `guide/ui.md` document handshake-token auth, the updated `pulse.ts` source, and room-join authorization: public rooms and the socket's own `user:<id>` / `private:user:<id>` are accepted, everything else is refused with `join:error`.
